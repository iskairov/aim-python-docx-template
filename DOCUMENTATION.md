## 1. Быстрый старт

Установка с помощью `pip`:

```bash
pip install docxtpl
```

Или с помощью `conda`:

```bash
conda install docxtpl --channel conda-forge
```

Базовый пример использования:

```python
from docxtpl import DocxTemplate

doc = DocxTemplate("my_word_template.docx")
context = {"company_name": "ООО «Мировая Компания»"}
doc.render(context)
doc.save("generated_doc.docx")
```

## 2. Введение

Библиотека использует два основных пакета:

- **python-docx** — для чтения, записи и создания поддокументов;
- **jinja2** — для управления тегами, вставленными в шаблон `.docx`.

`python-docx-template` была создана потому, что `python-docx` отлично подходит для создания документов с нуля, но крайне неудобен для изменения существующих сложных документов.

Подход работы с библиотекой:
1. Вы создаёте образец документа в Microsoft Word (или LibreOffice Writer) любой сложности: с картинками, таблицами, формулами, оглавлением, верхними и нижними колонтитулами, сносками и свойствами.
2. Прямо в редакторе Word вставляете в нужные места шаблонные теги в стиле Jinja2.
3. Сохраняете документ как файл `.docx` (формат OpenXML) — он становится вашим шаблоном.
4. Используете `python-docx-template` для генерации любого количества готовых документов Word из этого шаблона и словаря переменных контекста.

## 3. Синтаксис шаблонов в стиле Jinja2

Поскольку внутри используется движок Jinja2, в документе Word доступны все стандартные конструкции, циклы, условия и фильтры Jinja2. Однако из-за внутренней XML-структуры документа Word существуют важные особенности и специальные расширения.

### Ограничения

Обычные теги Jinja2 (`{% ... %}`, `{{ ... }}`) предназначены для использования внутри одного абзаца или одного текстового прогона (`run`) и не могут напрямую охватывать несколько абзацев, строк таблицы или столбцов, если не использовать специальные префиксы тегов.

> **Примечание:**
> В терминологии Microsoft Word **прогон (`run`, `<w:r>`)** — это непрерывная последовательность символов с одинаковым стилем форматирования. Например, если весь абзац написан одним шрифтом и начертанием, Word создаст один прогон. Если выделить одно слово в середине абзаца полужирным, Word разобьёт абзац на 3 прогона (обычный — полужирный — обычный). Библиотека `docxtpl` автоматически склеивает теги Jinja2, даже если Word разбил сам тег на несколько прогонов.

### Расширения для управления структурой Word

Чтобы управлять целыми абзацами, строками таблиц, столбцами таблиц, прогонами текста или математическими прогонами в формулах, используются специальные префиксы сразу после открывающего разделителя:

```jinja2
{%p тег_jinja2 %}  — для управления абзацами (<w:p>)
{%tr тег_jinja2 %} — для управления строками таблицы (<w:tr>)
{%tc тег_jinja2 %} — для управления столбцами/ячейками таблицы (<w:tc>)
{%r тег_jinja2 %}  — для управления текстовыми прогонами (<w:r>)
{%m тег_jinja2 %}  — для управления прогонами внутри математических формул (<m:r>)
```

При встрече таких тегов `python-docx-template` переносит чистый тег Jinja2 (без префикса `p`, `tr`, `tc`, `r`, `m`) на уровень соответствующего XML-контейнера, а сам абзац, строку, ячейку или прогон, содержавший управляющий тег, **удаляет** из итогового документа.

Например, если в шаблоне написано:

```jinja2
{%p if display_paragraph %}
Один или несколько абзацев текста
{%p endif %}
```

Первый и последний абзацы (содержащие `{%p ... %}`) никогда не попадут в готовый документ. Текст `Один или несколько абзацев текста` появится в документе только если `display_paragraph == True`.

> **ВАЖНО:**
> 1. Всегда ставьте пробел после префикса тега (`{%p if ... %}`, а не `{%pif ... %}`).
> 2. Внутри тегов `{%p ... %}`, `{%tr ... %}`, `{%tc ... %}`, `{%r ... %}` полностью поддерживаются операторы `%` (остаток от деления, например `{%tr if loop.index % 2 == 0 %}`) и словари `{...}` (исправлено в версии 0.21.0, Issue #660).
> 3. Не размещайте два управляющих тега `{%p` в одном и том же абзаце — каждый управляющий тег `{%p ... %}` должен находиться на отдельной строке (в отдельном абзаце).

### Вывод переменных

Для обычной подстановки значений используются двойные фигурные скобки:

```jinja2
{{ <var> }}
```

- Если `<var>` — строка, то управляющие символы `\n`, `\a`, `\t` и `\f` автоматически преобразуются соответственно в разрыв строки (`<w:br/>`), новый абзац (`<w:p>`), табуляцию (`<w:tab/>`) и разрыв страницы (`<w:br w:type="page"/>`).
- Если `<var>` — объект `RichText`, необходимо указать префикс `r` сразу после открывающих скобок:
  ```jinja2
  {{r <var> }}
  ```
- Если `<var>` — объект `RichTextParagraph` или `Subdoc`, рекомендуется использовать префикс `p`:
  ```jinja2
  {{p <var> }}
  ```

### Комментарии

Вы можете оставлять комментарии в шаблоне, которые будут полностью удалены вместе с содержащим их абзацем, строкой или ячейкой таблицы:

```jinja2
{#p комментарий на уровне абзаца #}
{#tr комментарий на уровне строки таблицы #}
{#tc комментарий на уровне ячейки таблицы #}
```

### Разбиение и склейка текста между абзацами

- Используйте `{%-` для склейки тега Jinja2 с концом предыдущего абзаца.
- Используйте `-%}` для склейки тега Jinja2 с началом следующего абзаца.

Это позволяет удобно записывать длинные условия на нескольких строках в Word:

```jinja2
Мой дом находится
{%- if living_in_town -%}
 в городе
{%- else -%}
 за городом
{%- endif -%}
 и мне это нравится.
```

> **Примечание:** Чтобы сохранить пробел в начале или конце склеиваемой строки в Word, используйте неразрывный пробел (`Ctrl+Shift+Space`). Теги `{%- ... -%}` должны располагаться на отдельных строках.

### Экранирование разделителей Jinja2

Если вам нужно вывести в итоговом документе сами последовательности `{%`, `%}`, `{{` или `}}`, используйте в шаблоне:

```text
{_%, %_}, {_{ или }_}
```

### Таблицы (объединение ячеек и цвет фона)

#### Горизонтальное объединение (`colspan` и `hm`)

1. Объединение на заданное число колонок:
   ```jinja2
   {% colspan <число_или_выражение> %}
   ```
   (см. `tests/dynamic_table.py`).
2. Горизонтальное объединение ячеек внутри цикла `{%tc for ... %}`:
   ```jinja2
   {% hm %}
   ```
   (см. `tests/horizontal_merge.py`).

#### Вертикальное объединение (`vm`)

Для вертикального слияния ячеек одного столбца внутри цикла по строкам `{%tr for ... %}` поместите в ячейку тег:

```jinja2
{% vm %}
```

Для вложенных циклов вы также можете указать собственное условие начала новой объединённой группы (исправлено в версии 0.21.0, Issue #620):

```jinja2
{% vm loop.first %}
{% vm item.is_group_start %}
```

#### Цвет заливки ячейки (`cellbg`)

Чтобы динамически задать цвет фона ячейки таблицы, поместите в начало ячейки тег:

```jinja2
{% cellbg <hex_код_цвета> %}
```

Переменная должна содержать шестнадцатеричный код цвета **без** символа `#` (например, `'FF0000'` или `'D9E1F2'`).

## 4. Работа с формулами Word (OMML) и сложными разрывами тегов

В Microsoft Word математические формулы хранятся в формате **OMML** (`<m:oMathPara>`, `<m:oMath>`). Когда пользователь вводит выражение `{{ my_var }}` в редакторе формул Word (`Alt + =`), Word:
1. Разбивает скобки `{`, `}`, знаки `_`, операторы и буквы на отдельные математические прогоны `<m:r><m:t>` с разными стилями (`<m:sty m:val="p"/>`).
2. Автоматически преобразует фигурные скобки `{...}` в структурные элементы разделителей `<m:d><m:dPr><m:begChr m:val="{"/><m:endChr m:val="}"/></m:dPr><m:e>...</m:e></m:d>`.
3. При вводе имени переменной с нижним подчёркиванием (например, `{{ mass_1 }}` или `{{ r_dist }}`) автоматически превращает часть после `_` в элемент нижнего индекса `<m:sSub>`.

Начиная с версии **0.21.0**, `docxtpl` автоматически распознаёт и нормализует все эти конструкции внутри `<m:oMath>`, а также склеивает разорванные теги в:
- математических формулах (`<m:t>`),
- обычном тексте и текстовых полях (`<w:t>`),
- кодах полей Word (`<w:instrText>`),
- фигурах, SmartArt и объектах DrawingML (`<a:t>`).

При этом настоящие математические индексы (например, $x_{\{\{ i \}\}}$, где тег `{{ i }}` целиком находится внутри индекса) полностью сохраняют свою математическую структуру!

## 5. Работа со свойствами документа и кастомными свойствами Word

Библиотека поддерживает полноценную работу со всеми тремя видами свойств документа `.docx`:

1. **Стандартные свойства (`docProps/core.xml`)** — `title`, `subject`, `author`, `keywords`, `comments`, `category`, `content_status`, `identifier`, `language`, `last_modified_by`, `version`, `revision`, `created`, `modified`, `last_printed`.
2. **Расширенные свойства приложения (`docProps/app.xml`)** — `Company` (Организация), `Manager` (Руководитель), `Application`, `AppVersion`, `Template`, `HyperlinkBase`.
3. **Пользовательские (кастомные) свойства Word (`docProps/custom.xml`)** — любые именованные свойства типов `str`, `int`, `float`, `bool`, `datetime.datetime`, `datetime.date`.

### Стандартные свойства (Core Properties)

Вы можете использовать теги Jinja2 прямо в свойствах файла в Word (*Файл -> Сведения -> Свойства*), и они будут автоматически отрендерены при вызове `tpl.render(context)`. Также доступны методы для чтения и записи из Python (без ограничения в 255 символов):

```python
tpl = DocxTemplate("template.docx")

# Чтение всех стандартных свойств в виде словаря
core_props = tpl.get_core_properties()

# Установка стандартных свойств
tpl.set_core_properties(
    title="Договор поставки № {{ num }}",
    author="Иванов И.И.",
    subject="Поставка оборудования",
    keywords="договор, поставка",
    comments="Автоматически сформированный документ",
)
```

### Расширенные свойства приложения (App Properties)

```python
# Чтение свойств из docProps/app.xml
app_props = tpl.get_app_properties()

# Запись свойств (поддерживают шаблоны Jinja2 при рендеринге)
tpl.set_app_properties(
    Company="ООО «{{ company_name }}»",
    Manager="Петров П.П.",
)
```

### Пользовательские (кастомные) свойства Word (Custom Properties)

Для работы с кастомными свойствами используется свойство `tpl.custom_properties` (реализующее интерфейс словаря `MutableMapping`) или методы `get_custom_properties()`, `set_custom_property()`, `set_custom_properties()`, `delete_custom_property()`:

```python
import datetime as dt
from docxtpl import DocxTemplate

tpl = DocxTemplate("template.docx")

# Установка пользовательских свойств разных типов
tpl.custom_properties["НомерДоговора"] = "ДГ-{{ contract_id }}"
tpl.custom_properties["Сумма"] = 250000.50          # float (vt:r8)
tpl.custom_properties["Этапов"] = 5                  # int (vt:i4 / vt:i8)
tpl.custom_properties["Согласован"] = True           # bool (vt:bool)
tpl.custom_properties["ДатаПодписания"] = dt.date(2026, 11, 15)  # date/datetime (vt:filetime)

# Массовое обновление
tpl.set_custom_properties({
    "Отдел": "Юридический департамент",
    "ВерсияМакета": 2,
})

# При вызове render() строковые кастомные свойства с тегами Jinja2 автоматически рендерятся!
tpl.render({"contract_id": "2026/99"})

# Чтение и удаление
print(tpl.get_custom_properties())
tpl.delete_custom_property("ВерсияМакета")

tpl.save("output.docx")
```

Если в исходном шаблоне `.docx` ещё не было файла `docProps/custom.xml`, он автоматически создаётся и регистрируется в пакете OpenXML.

### Автоматическое обновление полей DOCPROPERTY

Если в теле документа или колонтитулах вставлены поля Word `DOCPROPERTY "ИмяСвойства"` (как простые `<w:fldSimple>`, так и сложные `<w:fldChar>`), то при вызове `tpl.render()` и `tpl.save()` библиотека **автоматически обновляет отображаемый текст всех полей `DOCPROPERTY`** актуальными значениями из пользовательских, стандартных и расширенных свойств. Благодаря этому при открытии документа в Word, LibreOffice или конвертации в PDF новые значения видны сразу же без необходимости нажимать `Ctrl+A` -> `F9`.

При необходимости вы также можете принудительно вызвать `tpl.update_docproperty_fields()` или развернуть поля в обычный текст с помощью `tpl.custom_properties.dissolve_fields()`.

## 6. Форматированный текст (RichText)

При использовании обычного тега `{{ var }}` вставляемый текст наследует стиль того места в шаблоне, где стоял тег.
Если требуется динамически задавать цвет, шрифт, размер, начертание и другие атрибуты символов из кода Python, используйте объект `RichText` (или его краткий псевдоним `R`) в сочетании с тегом `{{r var }}`:

```python
from docxtpl import DocxTemplate, RichText, R

tpl = DocxTemplate("template.docx")

rt = RichText("Обычный текст, ")
rt.add("красный полужирный", color="#ff0000", bold=True, size=28)
rt.add(", подчёркнутый волной", underline="wave", italic=True)
rt.add(", с региональным шрифтом", font="eastAsia:微软雅黑")

context = {"my_richtext": rt}
tpl.render(context)
```

В шаблоне Word:

```jinja2
{{r my_richtext }}
```

Параметры метода `RichText.add()`:
- `style`: имя символьного стиля в Word (`w:rStyle`);
- `color`: цвет текста в HEX (`'ff0000'` или `'#ff0000'`);
- `highlight`: цвет фона (выделения) текста в HEX;
- `size`: размер в полупунктах (например, `24` соответствует 12 пт);
- `bold`, `italic`, `strike`: булевы флаги начертания;
- `underline`: `True` или тип линии (`'single'`, `'double'`, `'thick'`, `'dotted'`, `'dash'`, `'dotDash'`, `'dotDotDash'`, `'wave'`);
- `subscript`, `superscript`: нижний и верхний индекс;
- `font`: название шрифта (или `регион:шрифт`, например `'eastAsia:微软雅黑'`);
- `url_id`: идентификатор гиперссылки, созданный через `tpl.build_url_id(url)`;
- `rtl`: направление текста справа налево (`True`/`False`);
- `lang`: языковой код проверки орфографии (например, `'ru-RU'`).

### Гиперссылки в RichText

```python
tpl = DocxTemplate("your_template.docx")
rt = RichText("Перейдите на сайт ")
rt.add("Google", url_id=tpl.build_url_id("https://google.com"), color="0000FF", underline=True)
```

### Проверка на пустоту в условиях шаблона

Объекты `RichText`, `RichTextParagraph` и `Listing` реализуют метод `__bool__` (Issue #601). Если в `RichText()` не был добавлен текст, то в шаблоне условие `{% if my_richtext %}` вернёт `False`:

```jinja2
{%p if my_richtext %}
{{r my_richtext }}
{%p endif %}
```

## 7. Форматированные абзацы (RichTextParagraph)

Для генерации нескольких абзацев с заданными стилями абзаца Word используется класс `RichTextParagraph` (псевдоним `RP`) и тег `{{p var }}`:

```python
from docxtpl import DocxTemplate, RichText, RichTextParagraph

tpl = DocxTemplate("template.docx")
rp = RichTextParagraph()
rp.add(RichText("Первый абзац", bold=True), parastyle="Heading1")
rp.add("Второй абзац со стилем цитаты", parastyle="IntenseQuote")

tpl.render({"my_paragraphs": rp})
```

В шаблоне Word:

```jinja2
{{p my_paragraphs }}
```

## 8. Встраиваемые изображения (InlineImage)

Для динамической вставки изображений (PNG, JPEG и др.) в тело документа или колонтитулы используется класс `InlineImage` и обычный тег `{{ my_image }}`:

```python
from docx.shared import Mm
from docxtpl import DocxTemplate, InlineImage

tpl = DocxTemplate("template.docx")
img = InlineImage(
    tpl,
    image_descriptor="logo.png",
    width=Mm(30),
    height=Mm(15),
    anchor="https://example.com",  # Опциональная гиперссылка при клике на картинку
    title="Логотип",
    descr="Описание для чтения с экрана",
)

tpl.render({"logo": img})
tpl.save("output.docx")
```

В качестве `image_descriptor` можно передавать как путь к файлу, так и поток `io.BytesIO`.

## 9. Поддокументы (Subdoc)

Поддокумент (`Subdoc`) позволяет вставить в место тега `{{p mysubdoc }}` полноценный фрагмент документа Word (таблицы, списки, заголовки, картинки) или целый внешний файл `.docx`.

> **Важное улучшение (версия 0.21.0, Issue #631, #609):**
> Работа с `Subdoc` (включая слияние внешних файлов `.docx` с переносом стилей, картинок, списков и связей) теперь работает **из коробки** на чистых `python-docx` и `lxml`, не требуя обязательной установки пакета `docxcompose` и устаревшего `pkg_resources`! Если `docxcompose` установлен, он используется автоматически.

### Генерация поддокумента с нуля

```python
from docxtpl import DocxTemplate

tpl = DocxTemplate("master.docx")
sd = tpl.new_subdoc()
sd.add_heading("Раздел 1", level=1)
sd.add_paragraph("Абзац внутри поддокумента")

tpl.render({"mysubdoc": sd})
tpl.save("output.docx")
```

### Вставка внешнего файла .docx или объекта Document из памяти

Метод `tpl.new_subdoc()` принимает:
- путь к файлу (`str` или `PathLike`),
- поток `io.BytesIO`,
- уже созданный в памяти объект `docx.document.Document` (Issue #603):

```python
from docx import Document
from docxtpl import DocxTemplate

# Из файла на диске:
tpl = DocxTemplate("master.docx")
sd_from_file = tpl.new_subdoc("external_part.docx")

# Или из объекта python-docx Document в памяти:
mem_doc = Document()
mem_doc.add_paragraph("Создано в памяти")
sd_from_memory = tpl.new_subdoc(mem_doc)
```

### Удаление пустого завершающего абзаца

Чтобы избежать появления лишнего пустого абзаца после каждого поддокумента при вставке в цикле (Issue #629), передайте параметр `remove_trailing_paragraph=True`:

```python
sd = tpl.new_subdoc("part.docx", remove_trailing_paragraph=True)
```

## 10. Экранирование спецсимволов XML и класс Listing

Поскольку `.docx` внутри представляет собой XML, символы `<`, `>` и `&` в обычных строковых переменных могут нарушить валидность XML, если их не экранировать. Доступно 4 способа экранирования:

1. Включить автоэкранирование при вызове рендеринга:
   ```python
   tpl.render(context, autoescape=True)
   ```
2. Использовать фильтр Jinja2 `|e` в шаблоне: `{{ my_var|e }}`.
3. Экранировать строку в Python через `from html import escape` или фильтр `|listing`.
4. Использовать класс `Listing` — он автоматически экранирует спецсимволы XML и поддерживает переводы строк `\n`, новые абзацы `\a`, табуляции `\t` и разрывы страниц `\f`, сохраняя текущий стиль шаблона:
   ```python
   from docxtpl import Listing

   context = {
       "mylisting": Listing("Строка 1\nСтрока 2\aНовый абзац со знаками <>&")
   }
   ```

## 11. Замена изображений, медиафайлов и встроенных объектов (Excel, PowerPoint, Word)

### Замена картинок по имени или описанию (`replace_pic`)

Позволяет заменить картинку-заглушку в теле документа или колонтитулах без необходимости хранить исходный файл-заглушку на диске. Поиск выполняется по атрибутам `name`, `title`, `descr` (как в `<pic:cNvPr>`, так и в `<wp:docPr>` для совместимости с Word 2019/2021/365, Issue #618) и по имени файла ресурса:

```python
tpl.replace_pic("dummy_header_pic.jpg", "new_header_pic.jpg")
```

### Замена медиафайлов по CRC32 (`replace_media`)

Находит медиафайл внутри архива `.docx` по контрольной сумме CRC32 исходного файла-заглушки и заменяет его новым:

```python
tpl.replace_media("templates/dummy_pic.png", "new_pic.png")
```

### Замена встроенных объектов (`replace_embedded` и `replace_zipname`)

- Для замены встроенных документов Word (`.docx`) по CRC32:
  ```python
  tpl.replace_embedded("templates/embedded_dummy.docx", "real_doc.docx")
  ```
- Для замены встроенных таблиц Excel (`.xlsx`) и презентаций PowerPoint (`.pptx`) по пути внутри ZIP-архива `.docx`:
  ```python
  tpl.replace_zipname(
      "word/embeddings/Feuille_Microsoft_Office_Excel1.xlsx",
      "my_excel_file.xlsx",
  )
  ```
- При размножении встроенных объектов Excel/OLE в циклах Jinja2 библиотека автоматически генерирует уникальные `ShapeID`, `ObjectID` и клонирует встроенные потоки данных, чтобы в итоговом документе открывался каждый объект Excel (Issue #624).

## 12. Получение списка переменных шаблона (`get_undeclared_template_variables`)

Чтобы узнать, какие переменные используются в шаблоне (включая тело, колонтитулы, сноски и свойства документа) или каких переменных не хватает в переданном контексте:

```python
tpl = DocxTemplate("your_template.docx")

# Все переменные шаблона:
all_vars = tpl.get_undeclared_template_variables()

# Только те переменные, которых ещё нет в словаре context_dict:
missing_vars = tpl.get_undeclared_template_variables(context=context_dict)
```

## 13. Многократный рендеринг одного шаблона

Вы можете создать экземпляр `DocxTemplate` один раз и вызывать `render(context)` и `save(...)` в цикле для генерации множества документов. ## 14. Особенности Microsoft Word 2016+

Некоторые версии MS Word 2016 игнорируют символы табуляции `\t` и начальные пробелы в обычных подстановках. Для гарантированного сохранения табуляций и пробелов используйте `RichText` и тег `{{r ... }}`:

```python
tpl.render({
    "test_space_r": RichText("          "),
    "test_tabs_r": RichText(5 * "\t"),
})
```

## 15. Пользовательские и встроенные фильтры Jinja2

В окружении шаблона автоматически доступны встроенные фильтры (Issue #582):
- `|richtext(...)` или `|r(...)` — оборачивает значение в `RichText` (например, `{{r name|richtext(bold=True, color='ff0000') }}`);
- `|listing` — оборачивает значение в `Listing`;
- `|inline_image(width=..., height=...)` — создаёт `InlineImage` из пути или потока изображения.

Вы также можете передать собственное окружение `jinja2.Environment` с любыскими пользовательскими фильтрами:

```python
import jinja2
from docxtpl import DocxTemplate

def multiply_by(value, by):
    return value * by

doc = DocxTemplate("my_word_template.docx")
jinja_env = jinja2.Environment()
jinja_env.filters["multiply_by"] = multiply_by
doc.render({"price_dollars": 5.00}, jinja_env=jinja_env)
doc.save("generated_doc.docx")
```

## 16. Безопасность (защита от SSTI через SandboxedEnvironment)

Если файлы шаблонов `.docx` загружаются внешними или недоверенными пользователями, включите режим песочницы `sandbox=True` (Issue #644). В этом режиме используется `jinja2.sandbox.SandboxedEnvironment`, блокирующий доступ к внутренним атрибутам Python (например, `__class__`, `__mro__`, `__subclasses__`) и предотвращающий удалённое выполнение кода (RCE):

```python
tpl = DocxTemplate("untrusted_template.docx", sandbox=True)
tpl.render(context)
```

Или непосредственно при вызове `render`:

```python
tpl.render(context, sandbox=True)
```

## 17. Асинхронная работа (`asyncio`)

Для использования в асинхронных веб-сервисах (FastAPI, aiohttp, Litestar) предусмотрены корутины `render_async()` и `save_async()` (Issue #611):

```python
from docxtpl import DocxTemplate

async def generate_report(context: dict) -> None:
    tpl = DocxTemplate("template.docx")
    await tpl.render_async(context)
    await tpl.save_async("output.docx")
```

## 18. Запуск из командной строки (CLI)

Модуль `docxtpl` можно вызвать напрямую из терминала для генерации `.docx` из шаблона и JSON-файла с данными контекста (поддерживается кодировка UTF-8 и кириллица):

```bash
python -m docxtpl [-h] [-o] [-q] template_path json_path output_filename
```

Аргументы:
- `template_path` — путь к файлу шаблона `.docx`;
- `json_path` — путь к JSON-файлу с данными контекста;
- `output_filename` — путь для сохранения готового файла `.docx`;
- `-o`, `--overwrite` — перезаписать выходной файл без запроса подтверждения;
- `-q`, `--quiet` — не выводить информационные сообщения в консоль.
