.. Мастер-файл документации python-docx-template.

Добро пожаловать в документацию python-docx-template!
=====================================================

.. rubric:: Быстрый старт

Установка с помощью pip::

    pip install docxtpl

или с помощью conda::

    conda install docxtpl --channel conda-forge

Использование::

    from docxtpl import DocxTemplate

    doc = DocxTemplate("my_word_template.docx")
    context = {"company_name": "ООО «Мировая Компания»"}
    doc.render(context)
    doc.save("generated_doc.docx")

Введение
--------

Этот пакет использует два основных пакета:

- ``python-docx`` — для чтения, записи и создания поддокументов;
- ``jinja2`` — для управления тегами, вставленными в шаблон ``.docx``.

``python-docx-template`` был создан потому, что ``python-docx`` отлично подходит для создания документов с нуля, но неудобен для изменения существующих сложных документов.

Идея заключается в том, чтобы создать образец нужного документа в Microsoft Word — он может быть сколь угодно сложным: изображения, оглавления, колонтитулы, формулы, таблицы, сноски и пользовательские свойства.
Затем прямо в процессе редактирования документа в Microsoft Word вы вставляете в него теги в стиле Jinja2 и сохраняете документ в формате ``.docx`` (XML-формат) — он станет вашим файлом шаблона ``.docx``.

После этого вы можете использовать ``python-docx-template`` для генерации любого количества документов Word из этого шаблона и передаваемого словаря контекста.

Синтаксис в стиле Jinja2
------------------------

Поскольку используется пакет Jinja2, внутри документа Word можно применять все стандартные теги и фильтры Jinja2.
Тем не менее существуют некоторые ограничения и расширения, необходимые для корректной работы внутри XML-структуры документа Word:

Ограничения
+++++++++++

Обычные теги Jinja2 предназначены для использования внутри одного абзаца или прогона и не могут напрямую охватывать несколько абзацев, строк таблицы или прогонов без специальных префиксов.
Если вы хотите управлять абзацами, строками таблицы, столбцами или отдельным прогоном с его стилем, используйте специальный синтаксис тегов, описанный ниже.

**Примечание:**

«Прогон» (`run`) в Microsoft Word — это последовательность символов с одинаковым стилем.
Например, если вы создадите абзац, где все символы имеют один стиль, MS Word создаст внутри абзаца только один прогон.
Если вы выделите полужирным слово в середине этого абзаца, Word преобразует исходный прогон в 3 разных прогона (обычный — полужирный — обычный).

Расширения
++++++++++

Теги управления структурой
..........................

Для управления абзацами, строками таблиц, столбцами таблиц, прогонами текста и математическими прогонами в формулах используется специальный синтаксис::

   {%p jinja2_tag %}  — для абзацами (<w:p>)
   {%tr jinja2_tag %} — для строк таблицы (<w:tr>)
   {%tc jinja2_tag %} — для столбцов/ячеек таблицы (<w:tc>)
   {%r jinja2_tag %}  — для текстовых прогонов (<w:r>)
   {%m jinja2_tag %}  — для прогонов внутри математических формул (<m:r>)

При использовании этих тегов ``python-docx-template`` помещает настоящий тег Jinja2 (без префикса ``p``, ``tr``, ``tc``, ``r`` или ``m``) в нужное место XML-кода документа.
Кроме того, эти теги указывают ``python-docx-template`` **удалить** сам абзац, строку таблицы, столбец или прогон, в котором находился управляющий тег.

Например, если у вас есть такой шаблон::

   {%p if display_paragraph %}
   Один или несколько абзацев
   {%p endif %}

Первый и последний абзацы (содержащие теги ``{%p ... %}``) никогда не появятся в сгенерированном ``.docx`` независимо от значения ``display_paragraph``.
Текст ``Один или несколько абзацев`` появится только если ``display_paragraph`` истинно.

**ВАЖНО:** Всегда ставьте пробел после открывающего префикса тега и пробел перед закрывающим разделителем:

Избегайте::

   {%if something%}
   {%pif display_paragraph%}

Используйте::

   {% if something %}
   {%p if display_paragraph %}

**ВАЖНО:** Внутри выражений ``{%p ... %}``, ``{%tr ... %}``, ``{%tc ... %}``, ``{%r ... %}`` полностью поддерживаются символы ``%`` (оператор остатка от деления) и ``}`` (словари).

**ВАЖНО:** Не используйте ``{%p``, ``{%tr``, ``{%tc`` или ``{%r`` дважды в одном и том же абзаце, строке, столбце или прогоне.

Вывод переменных
................

Для вывода значений используются двойные фигурные скобки::

   {{ <var> }}

Если ``<var>`` — строка, символы ``\n``, ``\a``, ``\t`` и ``\f`` будут автоматически преобразованы в переводы строк, новые абзацы, табуляции и разрывы страниц соответственно.

Если ``<var>`` — объект RichText_, необходимо указать, что заменяется весь текущий прогон::

   {{r <var> }}

Обратите внимание на букву ``r`` сразу после открывающих скобок.

Комментарии
...........

Вы можете добавлять комментарии в стиле Jinja2 в свой шаблон::

   {#p комментарий на уровне абзаца #}
   {#tr комментарий на уровне строки таблицы #}
   {#tc комментарий на уровне ячейки таблицы #}

Разбиение и склейка текста
..........................

* Вы можете склеить тег Jinja2 с предыдущим абзацем с помощью ``{%-``
* Вы можете склеить тег Jinja2 со следующим абзацем с помощью ``-%}``

Пример::

   Мой дом находится
   {%- if living_in_town -%}
    в городской черте
   {%- else -%}
    в сельской местности
   {%- endif -%}
    и мне это нравится.

Экранирование разделителей
..........................

Чтобы вывести в тексте документа сами символы ``{%``, ``%}``, ``{{`` или ``}}``, используйте::

   {_%, %_}, {_{ или }_}

Таблицы
.......

Объединение ячеек
~~~~~~~~~~~~~~~~~

Вы можете объединять ячейки таблицы по горизонтали с помощью тега ``colspan``::

   {% colspan <var> %}

Также можно объединять ячейки горизонтально внутри цикла ``for``::

   {% hm %}

И объединять ячейки вертикально внутри цикла ``for`` (с опциональным условием для вложенных циклов)::

   {% vm %}
   {% vm loop.first %}

Цвет фона ячейки
~~~~~~~~~~~~~~~~

Чтобы изменить цвет фона ячейки таблицы, поместите в самое начало ячейки тег::

   {% cellbg <var> %}

``<var>`` должна содержать шестнадцатеричный код цвета *без* знака решётки ``#``.

Формулы Word (OMML)
-------------------

Библиотека полностью поддерживает замену переменных внутри математических формул Microsoft Word (``<m:oMath>`` и ``<m:oMathPara>``).
Даже если редактор формул Word разбил строку ``{{ my_var }}`` на несколько математических прогонов ``<m:r><m:t>``, обернул фигурные скобки в элемент разделителя ``<m:d>`` или преобразовал часть переменной после ``_`` в нижний индекс ``<m:sSub>``, ``docxtpl`` автоматически нормализует формулу и выполнит корректную подстановку значения.

Свойства документа и пользовательские свойства Word
---------------------------------------------------

При вызове ``tpl.render(context)`` шаблонные выражения Jinja2 автоматически рендерятся:

1. В стандартных свойствах документа (``docProps/core.xml``: ``title``, ``subject``, ``author``, ``keywords``, ``comments``, ``category``, ``content_status``, ``identifier``, ``language``, ``last_modified_by``, ``version``).
2. В расширенных свойствах приложения (``docProps/app.xml``: ``Company``, ``Manager``, ``Application``, ``AppVersion``, ``Template``, ``HyperlinkBase``).
3. В пользовательских (кастомных) свойствах Word (``docProps/custom.xml``).

Для управления кастомными свойствами из кода Python используйте ``tpl.custom_properties`` или методы ``set_custom_property()``, ``set_custom_properties()``, ``get_custom_properties()``, ``delete_custom_property()``::

   tpl = DocxTemplate("template.docx")
   tpl.custom_properties["НомерДоговора"] = "ДГ-{{ num }}"
   tpl.custom_properties["Сумма"] = 150000.0
   tpl.custom_properties["Подписан"] = True
   tpl.render({"num": "2026/01"})
   tpl.save("output.docx")

При сохранении и рендеринге все поля ``DOCPROPERTY`` в теле документа и колонтитулах автоматически обновляют свои отображаемые значения.

.. _RichText:

RichText
--------

Для динамического изменения символьного стиля (цвет, шрифт, размер, начертание, гиперссылки) используйте класс ``RichText`` (или ``R``) и тег ``{{r <var> }}``::

   tpl = DocxTemplate("your_template.docx")
   rt = RichText("Вы можете добавить гиперссылку, например на ")
   rt.add("Google", url_id=tpl.build_url_id("http://google.com"))

Объекты ``RichText``, ``RichTextParagraph`` и ``Listing`` поддерживают проверку на пустоту в условиях ``{% if my_richtext %}``.

RichTextParagraph
-----------------

Для динамического формирования абзацев со стилями абзаца используйте ``RichTextParagraph()`` (или ``RP()``) и тег ``{{p <var> }}``.

Встраиваемые изображения (InlineImage)
--------------------------------------

Для динамического добавления изображений в текст или колонтитулы используйте ``InlineImage``::

   myimage = InlineImage(tpl, image_descriptor="test_files/python_logo.png", width=Mm(20), height=Mm(10))

Поддокументы (Subdoc)
---------------------

Вы можете создавать поддокументы с нуля, загружать существующие файлы ``.docx`` или передавать объекты ``docx.Document`` из памяти (без обязательной установки ``docxcompose``)::

   tpl = DocxTemplate("templates/merge_docx_master_tpl.docx")
   sd = tpl.new_subdoc("templates/merge_docx_subdoc.docx", remove_trailing_paragraph=True)
   tpl.render({"mysubdoc": sd})
   tpl.save("output/merge_docx.docx")

.. _Escaping:

Экранирование (Escaping)
------------------------

Для защиты XML от спецсимволов ``<``, ``>`` и ``&`` можно использовать:

* ``tpl.render(context, autoescape=True)``
* Фильтр ``{{ <var>|e }}`` или ``{{ <var>|listing }}`` в шаблоне
* Объект ``Listing(text)`` в контексте
* Объект ``RichText(text)`` с тегом ``{{r <var> }}``

Замена картинок, медиа и встроенных объектов
--------------------------------------------

* ``tpl.replace_pic("dummy_header_pic.jpg", "header_pic_i_want.jpg")`` — замена изображения по имени файла, заголовку (title) или описанию (alt text).
* ``tpl.replace_media("dummy_header_pic.jpg", "header_pic_i_want.jpg")`` — замена медиафайла по контрольной сумме CRC32.
* ``tpl.replace_embedded("embedded_dummy.docx", "embedded_docx_i_want.docx")`` — замена встроенного документа по CRC32.
* ``tpl.replace_zipname("word/embeddings/Feuille_Microsoft_Office_Excel1.xlsx", "my_excel_file.xlsx")`` — замена файла внутри ZIP-структуры ``.docx``.

Получение переменных шаблона
----------------------------

Для получения списка всех переменных шаблона (или недостающих в контексте переменных)::

   tpl = DocxTemplate("your_template.docx")
   set_of_variables = tpl.get_undeclared_template_variables(context=context_dict)

Безопасность (SandboxedEnvironment) и Asyncio
---------------------------------------------

* Для защиты от SSTI при работе с недоверенными шаблонами используйте ``DocxTemplate("tpl.docx", sandbox=True)`` или ``tpl.render(context, sandbox=True)``.
* Для асинхронной работы используйте ``await tpl.render_async(context)`` и ``await tpl.save_async("out.docx")``.

Запуск из командной строки
--------------------------

::

   usage: python -m docxtpl [-h] [-o] [-q] template_path json_path output_filename
